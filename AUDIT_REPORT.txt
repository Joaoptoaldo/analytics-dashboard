## 4. IDENTIFICAÇÃO DE INCONSISTÊNCIAS E PROBLEMAS (Terceiro Loop)

### CRÍTICO - Quebra de Verdade

Nenhum problema crítico encontrado. Todos os valores numéricos coincidem 
com precisão entre DB → API → Frontend.

═══════════════════════════════════════════════════════════════════════════════

### SEMÂNTICO - Dados corretos, representação enganosa

#### PROBLEMA #1: Dados Sintéticos Misturados com Dados Reais
**Componente**: Top Products (gráfico de barra + tabela)
**O quê mostra**: Annibale Colombo Sofa, Annibale Colombo Bed, client_0, client_1, client_2
**O porquê é problema**: 
  - Annibale Colombo = produtos reais do DummyJSON
  - client_0, client_1, client_2 = placeholders do dataset de seed (backend/data.py)
  - Visual não diferencia dados reais de dados sintéticos
  - Usuário não sabe se está vendo dados de negócio ou de teste

**Causa provável**: [backend/models/product.py] - modelo não tem flag/marker para origem
             [backend/data.py] - seed data mescla client_N com nomes de produtos reais

**Classificação**: SEMÂNTICO - Aritmética está correta, mas contexto é enganoso

---

#### PROBLEMA #2: Categorias Placeholder (A, B, C) em Distribuição
**Componente**: Distribuição por Categoria (pie chart)
**O quê mostra**: groceries (24%), B (16%), A (16%), C (15%), furniture (8%), ...
**O porquê é problema**:
  - Categorias A, B, C = placeholders do seed (backend/data.py)
  - Categorias reais = beauty, fragrances, furniture, groceries
  - Visual agrupa dados reais com placeholders sem aviso

**Causa provável**: [backend/seeds/seed_data.py] line ~15-19
             Seed insere records com category='A'/'B'/'C' indiscriminadamente

**Classificação**: SEMÂNTICO - Agregação está certa, mas dataset é misto

---

### VISUAL - Pode induzir erro, mas cálculo está correto

#### PROBLEMA #3: Granularidade Enganosa do Gráfico Temporal
**Componente**: "Vendas Temporais - série diária" (LineChart)
**O quê mostra**: 
  - Label: "Janela ativa: Todo o histórico"
  - Título: "série diária"
  - Realidade: Mostra dados MENSAIS quando period=all

**O porquê é problema**:
  - Usuário lê "série diária" e espera ver cada dia
  - Mas o código mapeia dados mensais para período all
  - Frontend em [src/Dashboard.tsx] linha 136-146 mapeia salesMonthly para formato diário
  - Resultado: picos visuais parecem ser dias, mas são meses

**Causa provável**: [src/Dashboard.tsx] linha 136-146
  ```
  const salesTrendData = useMemo(() => {
    if (period === 'all') {
      const monthly = salesMonthly || []
      return monthly.map((m) => ({ period: `${m.month}-01`, revenue: m.revenue, orders: m.orders }))
    }
    return salesTrend || []
  }, [period, salesMonthly, salesTrend])
  ```
  Mapeia monthly → "YYYY-MM-01" format, fake daily granularity

**Classificação**: VISUAL - Rótulo enganoso, dados corretos

---

#### PROBLEMA #4: Eixo Temporal Truncado no Gráfico
**Componente**: LineChart x-axis labels
**Visual mostra**: "31/05/2025" to "28/02/2026"
**Esperado (DB)**: "2025-06-25" to "2026-05-03"
**O porquê é problema**:
  - Visual trunca/arredonda datas do eixo
  - Usuário não vê verdadeiro primeiro e último ponto
  - Pode parecer que dados começam/acabam em datas diferentes

**Causa provável**: [backend/services/analytics.py] get_sales_trend() ou 
            [src/Dashboard.tsx] formatTick() function
            Recharts interpola/arredonda labels para evitar sobreposição

**Classificação**: VISUAL - Formatação de eixo, números estão corretos

---

#### PROBLEMA #5: Percentuais Arredondados no Pie Chart
**Componente**: Distribuição por Categoria (pie labels)
**Visual mostra**: 24%, 16%, 16%, 15%, 8%, 8%, 8% (totalizando 99% ou 100%?)
**Esperado (exato)**: 24.19%, 16.13%, 16.13%, 14.52%, 8.06%, 8.06%, 8.06% (= 99.99%)
**O porquê é problema**:
  - Arredondamento pode causar ilusão de que soma é exatamente 100%
  - Pode parecer haver 1% faltando ou não
  - Usuário não sabe se é truncado ou se há categoria oculta

**Causa provável**: [src/Dashboard.tsx] renderCategoryPieLabel() line ~200
            Recharts aplica toFixed(0) ao percentual

**Classificação**: VISUAL - Precisão de exibição, agregação está correta

## 6. DIAGNÓSTICO TÉCNICO

### PROBLEMA #1: Dados Sintéticos em Top Products
**Tipo de erro**: DATASET INCONSISTENTE / DADO MISTO
**Localização**: 
  - Dados: [backend/data.py] _build_seed_data() + sync real
  - Exibição: [src/Dashboard.tsx] topProducts rendering
**Raiz**:
  - Seed data não é segregado de dados reais
  - Modelo Product não diferencia origem
  - Frontend não filtra/marca dados de teste

---

### PROBLEMA #2: Categorias Placeholder em Distribuição
**Tipo de erro**: DATASET INCONSISTENTE / METADATA ENGANOSA
**Localização**:
  - Dados: [backend/seeds/seed_data.py] linha 15-19
  - Query: [backend/services/analytics.py] get_distribution_category()
**Raiz**:
  - Seed insere categorias genéricas A/B/C
  - Não há forma de filtrar/excluir em query
  - Frontend não sabe que são placeholders

---

### PROBLEMA #3: Título "série diária" mas dados mensais
**Tipo de erro**: DISCREPÂNCIA DE GRANULARIDADE / RÓTULO ENGANOSO
**Localização**:
  - Frontend: [src/Dashboard.tsx] linha 223 (salesTrendRangeLabel)
  - Mapeamento: linha 136-146 (salesMonthly → daily format fake)
  - Renderização: linha 400 (CardTitle mostra "série diária")
**Raiz**:
  - Code mapeia mensais como se fossem diários (YYYY-MM-01)
  - Rótulo não foi atualizado quando mudou de behavior
  - Usuário lê "diária" e espera granularidade que não existe

---

### PROBLEMA #4: Eixo x truncado
**Tipo de erro**: FORMATAÇÃO DE EIXO / ROUNDING DOS LABELS
**Localização**:
  - Recharts interpolação automática
  - [backend/services/analytics.py] data points gerados corretamente
**Raiz**:
  - Recharts reduz labels para evitar overflow
  - Backend envia dados corretos (2025-06-25 to 2026-05-03)
  - Frontend recebe e grafica corretamente internamente
  - Apenas labels de eixo são truncados (não é erro, é feature)

---

### PROBLEMA #5: Percentuais em pie com rounding
**Tipo de erro**: PRECISÃO DE EXIBIÇÃO / ROUNDING VISUAL
**Localização**:
  - [src/Dashboard.tsx] renderCategoryPieLabel()
  - Recharts aplica toFixed(0) ao percent
**Raiz**:
  - Cálculo correto: 24.19% → 24% arredondado
  - Pode parecer 1% faltando, mas agregação está 99.99%
  - é trade-off readabilidade vs. precisão

## 7. PROPOSTAS DE CORREÇÃO

### Para PROBLEMA #1: Dados Sintéticos em Top Products

**Correção Mínima (Rápida)**:
  1. Adicionar flag `is_synthetic: bool` ao modelo Product
  2. Marcar seed data com `is_synthetic=True` em [backend/seeds/seed_data.py]
  3. Filter no ranking: `WHERE is_synthetic=False` em [backend/services/analytics.py]
  Impacto: 2 arquivos, ~10 LOC, sem quebra de compatibilidade

**Correção Ideal (Robusta)**:
  1. Criar tabela separada `SyntheticProduct` para dados de teste
  2. Seed insere em SyntheticProduct, não em Product
  3. Queries default filtram synthetic, há endpoint opcional para teste
  Impacto: 3-5 arquivos, ~50 LOC, requer migration

---

### Para PROBLEMA #2: Categorias Placeholder

**Correção Mínima**:
  1. Definir enum de categorias válidas
  2. Seed usa apenas categorias reais: beauty, fragrances, groceries, furniture, ...
  3. Remover A, B, C do seed
  Impacto: 2 arquivos, ~5 LOC

**Correção Ideal**:
  1. Auto-generate categorias baseado em real data (DummyJSON)
  2. Seed valida contra enum antes de insert
  3. Frontend mostra badge "real data" vs "seed data"
  Impacto: 3 arquivos, ~30 LOC

---

### Para PROBLEMA #3: Rótulo "série diária" enganoso

**Correção Mínima**:
  1. Renomear label em [src/Dashboard.tsx] linha 223
     FROM: "série diária"
     TO: "série mensal (agregação completa)"
  2. Adicionar comentário explicando o mapeamento
  Impacto: 1 linha

**Correção Ideal**:
  1. Detectar granularidade real em frontend
  2. Mostrar label dinâmico baseado em period
     if period === 'all': "série mensal"
     if period === '30d': "série diária"
     etc.
  Impacto: 1 arquivo, ~5 LOC

---

### Para PROBLEMA #4: Eixo temporal

**Correção Mínima**:
  Sem ação necessária - é comportamento esperado de Recharts
  
**Correção Ideal** (se critical):
  1. Customizar intervalo de labels manualmente
  2. Forçar display de min/max dates mesmo que sobreponha
  Impacto: 1 arquivo, ~10 LOC (Recharts config)

---

### Para PROBLEMA #5: Percentuais arredondados

**Correção Mínima**:
  Deixar como está - é trade-off legítimo

**Correção Ideal**:
  1. Mostrar percentual com 1 decimal em hover
  2. Label em pie apenas com 0 decimais (visual limpo)
  Impacto: 1 arquivo, ~3 LOC

## 8. VEREDITO FINAL

### O dashboard é: **PARCIALMENTE CONFIÁVEL** 

**Justificativa**:

 CONFIÁVEL (Aritmética):
  - Todos os totais (receita, pedidos, clientes) estão corretos
  - Agregações (soma, contagem, percentuais) estão matematicamente corretas
  - Queries backend retornam dados sem distorção

  - Falta clareza visual sobre origem dos dados
